# V3.9 Agent et négociation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** négocier salaire et durée des offres professionnelles, avec agent facultatif, commissions transparentes et sauvegardes compatibles.

**Architecture:** calculs de négociation purs, état versionné et commandes moteur autoritaires. Intégrations limitées à la création des offres, à la signature et au flux financier quotidien ; vues distinctes de ces calculs. Les règles de match restent celles de V3.8.

**Tech Stack:** modules JavaScript natifs, Node `node:test`, Playwright/Chromium, IndexedDB, service worker, GitHub Actions/Pages. Aucune dépendance produit supplémentaire.

**Spec:** `docs/superpowers/specs/2026-10-09-v39-agent-design.md`, validée le 9 octobre 2026.

## Global Constraints

- Autogestion gratuite ; mandats local/national/international : commissions 1/2/3 % du salaire net simulé, marges additionnelles 1/3/5 points.
- Deux contre-offres maximum par offre ; demandes salariales 0/+5/+10/+15 % depuis le salaire initial, jamais cumulées ; durées initiale −1/initiale/+1, bornées à 1–4 ans.
- Marge sportive `clamp(2 + écart / 2, 0, 10)` ; marge totale plafonnée à 15 %. Respecter le budget sans invalider rétroactivement l’offre initiale.
- Année supplémentaire possible seulement à âge ≤30 et écart au poste ≥0. Rôle et minutes ne sont pas négociés.
- Mandat figé par session et contrat ; aucun prélèvement rétroactif, aucun coût de sélection, aucun frais sur sponsors/placements, aucune dette.
- Offres amateur/draft/migrées exemptes et non négociables ; pas de signature automatique nouvelle.
- Historique de 40 négociations maximum ; cumuls persistants ; compteurs, devis et commissions idempotents.
- Version application 3.9.0, schéma 4 conservé ; `rulesVersion` des nouveaux matchs reste 3.8.0. Aucun remplacement aveugle de toutes les chaînes de version.
- Migrations V3.0–V3.8, match en cours et RNG conservés, secours avant conversion ; mode et destination de simulation conservés.
- Sans action nouvelle : mêmes résultats que V3.8, hors version et sous-état neutre.
- Travailler dans `work/hoop-legacy-v3.9`, depuis la V3.8 publiée `c657ca01438fa000cebd9dd474ce445fa70ed614` ; pas de modification de main pendant le développement.
- La revue V3.8 interrompue n’est pas une approbation et ne sera pas relancée par une autre voie. Signaler séparément toute limitation de revue V3.9.

## Review Focus

1. Double clic ou ancien devis après rechargement : une tentative/signature seulement, pas de modification partielle — tâches 2/3/6.
2. Ancienne décision de contrat pendant migration : offre inchangée et signable sans frais, aucun blocage de carrière — tâche 5.
3. Changement d’agent après signature ou contrat arrivé à zéro : taux d’origine conservé sur le revenu réellement versé, nouveau contrat sans double suivi — tâche 4.
4. Club déjà au-dessus de son budget : offre initiale préservée, aucun supplément salarial permis — tâches 2/3.
5. Historique dont les anciens partenaires/effectifs ont changé : import valide, compteurs mal typés refusés, texte affiché sans balisage interprété — tâches 1/5/6.

## Structure et contrats partagés

Créer `dist/representation-catalog.js`, `representation-state.js`, `negotiation.js`, `representation.js`, `representation-view.js`. Le module de commandes `representation.js` relie l’état, les calculs purs et les données préparées par le moteur ; il n’importe pas `engine.js`, `finance.js` ou `commands.js`. Les gardes sont fournies par les points d’entrée et répétées sur l’état minimal dans les commandes (retraite, match, décision).

`representation` : `{version:1,mandate:'self',nextId:1,session:null,contract:null,history:[],totals:{commission:0}}`.
Session : `{id,day,mandate,offers:[]}`. Entrée d’offre : `{offerId,initial,current,limits,attempts:0,revision:0,eligible}` ; `initial/current` contiennent salaire et années, les autres champs restent dans `s.offers`.
Suivi signé : `{id,offerId,team,mandate,rate,started,commission:0}`. Un suivi exempt emploie mandat `self`, taux zéro. Les cumuls historiques ne sont pas recréés à partir d’un contrat ancien.
Devis : `{sessionId,offerId,revision,request:{raise,years},response:{salary,years,outcome,reasons},fingerprint}` ; pas de référence objet mutable à l’état. Le fingerprint représente les entrées pertinentes, sans utiliser de tirage RNG.
Résultat de commande : `{ok:boolean,reason:string}` ; échec sans mutation. Les vues ne signent jamais des montants fournis par l’utilisateur.
